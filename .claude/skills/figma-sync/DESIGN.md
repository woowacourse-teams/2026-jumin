# figma-sync 설계 문서

이 문서는 `figma-sync` 스킬의 명세와 설계 이유를 정리한다. 실행 절차는 `SKILL.md`에 있다. 이 문서는 스킬을 고치거나 이해할 때 읽는다. 스킬을 실행할 때는 읽지 않아도 된다.

## 1. 목적과 범위

Figma에서 디자인을 고친 뒤 `/figma-sync`를 부르면, 바뀐 디자인만 찾아 서비스 코드에 반영한다.

- **방향:** Figma → 코드 단방향. 디자인 원천은 Figma다. 코드에서 Figma로 자동으로 보내지 않는다.
- **실행 시점:** 사람이 부를 때만 실행한다. 저장 감지, 웹훅, CI 자동 실행은 없다.
- **반영 방식:** 바뀐 항목을 보여 주고, 사람이 고른 것만 코드에 반영한다.
- **대상:**
  - Figma 파일 `주차의-민족-UI`의 변수 컬렉션
  - 텍스트·효과 스타일
  - Component 페이지의 공용·도메인 컴포넌트
  - Screens 페이지의 화면

## 2. 설계를 정한 제약

| 제약                | 내용                                                                                                   | 설계에 준 영향                                                    |
| ------------------- | ------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| Figma MCP 호출 한도 | Full 좌석 기준 하루 200회. View·Collab 좌석은 한 달 20회                                               | 실행마다 Figma 전체를 읽을 수 없다.                               |
| Figma 응답 크기     | Component 페이지 노드 목록 한 번이 17만 자를 넘었다. 컴포넌트 하나의 `get_design_context`도 수천 자다. | 큰 응답을 대화로 가져오지 않고 Figma 안에서 줄여야 한다.          |
| 변경 이력이 없음    | Figma는 "이 노드가 언제 바뀌었는지"를 노드 단위로 알려 주지 않는다.                                    | 바뀐 것을 알려면 이전 상태를 직접 저장해야 한다.                  |
| Variables REST API  | Enterprise 플랜 전용이다.                                                                              | CI에서 변수를 읽는 방식은 쓸 수 없다. MCP의 `use_figma`로 읽는다. |
| AI 판단의 흔들림    | 같은 디자인을 읽어도 실행마다 결과가 조금씩 다를 수 있다.                                              | "바뀌었는지"는 규칙으로 정하고, AI는 해석만 한다.                 |

## 3. 핵심 설계: 스냅숏과 지문

마지막으로 동기화했을 때의 Figma 상태를 `snapshot.json`에 지문(hash)으로 저장한다. 실행할 때는 Figma 안에서 지금 상태의 지문을 다시 계산하고, 저장된 지문과 다른 항목만 돌려받는다.

```text
snapshot.json(지난 지문) ──▶ make-call.mjs ──▶ use_figma(detect.js)
                                                   │ Figma 안에서 지문 계산·비교
                                                   ▼
                                     달라진 항목만 + 현재 속성 요약(spec)
                                                   │
                         AI: 코드와 대조 → 표로 보고 → 사람이 선택 → 코드 수정
                                                   │
                         pnpm design:check → snapshot.json에서 반영한 항목만 갱신
```

### 역할 분담

| 단계                    | 담당                          | 이유                                                                     |
| ----------------------- | ----------------------------- | ------------------------------------------------------------------------ |
| 무엇이 바뀌었나         | 스크립트(`detect.js`)         | 같은 상태면 항상 같은 결과가 나와야 한다. 1px 차이도 놓치지 않아야 한다. |
| 코드의 어디에 해당하나  | AI                            | 토큰 이름 대응, 파일 찾기, 의도 주석 해석은 판단이 필요하다.             |
| 반영할지                | 사람                          | 디자인 의도는 사람이 확인한다.                                           |
| 어떻게 고치나           | AI                            | 기존 컴포넌트와 theme 토큰 패턴에 맞춰 고친다.                           |
| 고친 결과가 규칙에 맞나 | 스크립트(`pnpm design:check`) | 색상 값을 직접 썼는지는 기계적으로 검사한다.                             |

### 지문에 넣는 것과 넣지 않는 것

지문은 `detect.js`의 `spec` 함수가 만든 요약을 FNV-1a로 해시한 값이다.

- **넣는 것:**
  - 타입, 이름, 크기
  - 오토레이아웃(방향·패딩·간격·정렬·최소 높이)과 연결된 변수
  - radius와 연결된 변수
  - 채우기·선과 연결된 색 변수, 선 두께
  - 효과 스타일, 불투명도
  - 텍스트 스타일과 글자
  - 컴포넌트 속성
  - 인스턴스의 원본 이름·속성 값·덮어쓴 속성·글자
- **넣지 않는 것:**
  - 노드의 x·y 위치. 캔버스 배치를 옮기는 것까지 변경으로 잡지 않기 위해서다. 그래서 절대 위치 요소(예: Modal 닫기 버튼)의 위치만 바뀌면 찾지 못한다.
  - 인스턴스 안쪽 구조. 원본 컴포넌트는 자기 지문이 따로 있다. 그래서 원본만 바뀌었을 때 그 원본을 쓰는 화면까지 변경으로 잡히지 않는다.
  - 이미지 내용과 벡터 경로

변경 요약(`spec`)은 컴포넌트당 최대 120개 노드까지 돌려준다. 결과가 6만 자를 넘으면 요약을 빼고 `get_design_context`로 읽도록 안내한다.

## 4. 파일 명세

| 파일                    | 형식                                                                                                                                                   | 비고                                                                                                                                                                    |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SKILL.md`              | 실행 절차                                                                                                                                              | 스킬을 부를 때마다 읽힌다. 짧게 유지한다.                                                                                                                               |
| `DESIGN.md`             | 이 문서                                                                                                                                                | 실행 중에는 읽지 않는다.                                                                                                                                                |
| `pages.json`            | `fileKey`, `pages[].{name, nodeId, sections[], variableFrames[], ignore[]}`, `ignorePages[]`                                                           | Figma 구조가 바뀌면 노드 ID를 고친다.                                                                                                                                   |
| `snapshot.json`         | `syncedAt`, `collections.{이름: 지문}`, `styles.{text, effect}`, `components.{id: {name, section, code, hash}}`, `screens.{id: {name, section, hash}}` | 커밋해서 팀이 같은 기준을 쓴다.                                                                                                                                         |
| `scripts/detect.js`     | Figma 안에서 실행하는 코드                                                                                                                             | 위에서부터 자리표시자 → 공용 `spec` → `@components` 블록 → `@screens` 블록 순서다.                                                                                      |
| `scripts/make-call.mjs` | `node make-call.mjs <components\|screens> [--init] [--only 이름,이름]`                                                                                 | 대상이 아닌 블록을 잘라 내고, 자리표시자를 채워 출력한다. `--only`는 기준(`snapshot.json`)에 같은 이름이 있으면 정확히 일치(`=` 접두사)로, 없으면 포함으로 바꿔 넘긴다. |

### 비교 결과 형식

- **components:**
  - `collections`: 바뀐 컬렉션의 전체 값
  - `styles`: 바뀐 스타일 목록
  - `added`, `changed`: 컴포넌트 `{id, name, section, code, hash, spec}`
  - `removed`: 사라진 컴포넌트 ID
  - `next`: 반영 후 저장할 새 지문
- **screens:** `added`, `changed`, `removed`(화면 이름만)와 `next`
- **`--init`:** 바뀐 것만이 아니라 모든 지문을 `next` 형식으로 돌려준다.

### 코드 경로를 찾는 순서

`snapshot.json`의 `code`는 코드 경로다. 다음 순서로 찾는다.

1. 아이콘(`Icon/…`)이면 `src/shared/components/ui/icons/index.ts`
2. Component 페이지 카드의 `코드 …` 글
3. 컴포넌트 설명의 `코드 src/…` 또는 `코드 assets/…`

Figma에 새로 생긴 컴포넌트는 코드를 만든 뒤 설명 첫 줄에 `코드 <경로>`를 넣는다. 그래야 다음부터 경로를 찾을 수 있다.

## 5. 비용

2026-11-18 기준 실측이다. 컴포넌트 60개, 화면 12개, 변수 컬렉션 7개다.

| 상황                                    | Figma 호출                                      | 대화에 들어오는 양                           |
| --------------------------------------- | ----------------------------------------------- | -------------------------------------------- |
| 바뀐 것 없음                            | 3회 (세션 1, 컴포넌트 1, 화면 1)                | 빈 결과                                      |
| 컴포넌트 하나 변경 (Modal 사례)         | 3회                                             | 그 컴포넌트의 요약 약 1천 자                 |
| 구조 변경·새 컴포넌트                   | 3회 + 해당 컴포넌트 수만큼 `get_design_context` | 그 컴포넌트들                                |
| 참고: 스크립트 없이 AI가 전부 읽는 경우 | 약 75회 이상                                    | 컴포넌트 60개 전체. 노드 목록만 17만 자 이상 |

실행 코드는 컴포넌트 비교가 약 9.8KB, 화면 비교가 약 6.1KB다. 이 코드는 매 실행 AI가 `use_figma`에 그대로 넘긴다.

| 새 컴포넌트는 승인 후 코드 생성            | 코드 위치와 구조는 사람이 확인하는 게 안전하다.                                                                            | 보고만, 자동 생성                   |

| Tokens Studio·Variables REST API 미사용    | Tokens Studio는 별도 플러그인과 형식 변환이 필요하고, REST API는 Enterprise 전용이다.                                      | Tokens Studio GitHub 동기화         |

## 7. 알려진 한계

- **이전 값을 모른다.** 지문은 "달라졌다"만 알려 준다. "28 → 0" 같은 이전 값은 코드 값과 비교해 추정한다. 실수로 바뀐 경우는 사람이 "무시"로 걸러야 한다.
- **위치 변경을 못 찾는다.** x·y 위치는 지문에 없다.
- **원본 컴포넌트 변경이 화면에 전파되는 건 화면 변경으로 잡지 않는다.** 원본 컴포넌트의 변경으로만 보고된다.
- **코드만 바뀐 경우는 모른다.** 기준은 Figma 쪽 상태다. 코드를 직접 고쳐 Figma와 어긋나면 찾지 못한다. 가끔 전체 비교(`--init` 후 코드 대조)로 확인한다.
- **Figma 텍스트 스타일에는 자간을 넣지 않는다.** 스타일에 자간을 덮어쓰면 스타일 연결이 끊기기 때문이다. 코드의 자간은 차이로 보지 않는다.
- **Figma 구조가 크게 바뀌면 기준을 다시 만들어야 한다.** 예를 들어 섹션이나 페이지를 다시 만들면 노드 ID가 바뀐다.

## 8. 고칠 때 지킬 것

- **`spec` 함수를 바꾸면** 모든 지문이 달라진다. 같은 변경 안에서 `--init`으로 기준을 다시 만들고 `snapshot.json`을 함께 커밋한다.
- **Figma 섹션이나 페이지를 옮기거나 새로 만들면** `pages.json`의 노드 ID를 먼저 고친다.
- **지문에 속성을 추가할 때는** 비용(결과 크기)과 거짓 변경(캔버스 배치 같은 의미 없는 차이)을 함께 따진다.
- **`SKILL.md`는 짧게 유지한다.** 실행마다 읽히기 때문이다. 배경 설명은 이 문서에 쓴다.
