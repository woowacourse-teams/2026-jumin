# 커밋

커밋하기 전에 `docs/team-conventions.md`를 읽고 팀 규칙을 따른다.

## 작업 절차

1. `git status`와 전체 diff를 확인해 커밋 범위를 정한다. 사용자의 관련 없는 변경 사항은 제외한다.
2. 현재 브랜치가 `<github-nickname>/`으로 시작하는지 확인한다. 태스크 번호가 있으면 `TSK-<number>`를 사용하고, 없으면 작업을 짧게 나타낸 kebab-case 설명을 사용한다. `main`이나 `develop`에 직접 커밋하지 않는다.
3. 관련 테스트, 린트, 타입 검사, 빌드를 실행한다. 실행할 검증 명령이 없으면 그 사실을 명시한다.
4. `<type>(<optional-scope>): <summary>` 형식의 AngularJS 컨벤션 커밋 메시지를 선택한다. 요약은 문장 종결 어미 없이 간결한 한글 단답형으로 작성한다. 예: `분리`, `추가`, `수정`.
5. 커밋 전에 변경 파일, 검증 결과, 커밋 메시지를 요약한다. 커밋 범위가 모호하거나 사용자의 관련 없는 변경 사항이 포함되면 확인을 요청한다.
6. 의도한 파일만 스테이징하고, 스테이징된 diff를 다시 확인한 뒤 커밋한다.

## 주의 사항

- 자격 증명, 로컬 환경 파일, 관련 없는 작업을 커밋에 포함하지 않는다.
- 작업 ID는 선택 사항이다. 있는 경우에만 브랜치와 후속 PR에 기록한다.
- 이 스킬은 PR을 만들거나 병합하지 않는다. PR 작업은 `$create-pull-request` 스킬을 사용한다.
