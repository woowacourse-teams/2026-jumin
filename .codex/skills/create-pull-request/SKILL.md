# PR 생성

PR을 만들기 전에 `docs/team-conventions.md`와 `.github/pull_request_template.md`를 읽고 팀 규칙을 따른다.

## 작업 절차

1. `git status`, 현재 브랜치, 대상 브랜치와의 diff를 확인한다. 커밋하지 않은 변경 사항은 PR에 포함되지 않음을 알린다.
2. 현재 브랜치가 `<github-nickname>/tsk-<number>` 형식을 따르고 `develop`에서 생성됐는지 확인한다. 작업 ID가 없으면 PR을 만들지 않는다.
3. PR에 포함될 커밋과 관련 테스트, 린트, 타입 검사, 빌드 결과를 확인한다. 검증이 없으면 그 사실을 PR에 기록한다.
4. 레포지토리 템플릿에 맞춰 작업 ID, 주요 변경 사항, 관련 이슈 또는 문서, 리뷰어 참고 사항을 작성한다.
5. `develop`을 대상으로 PR을 만들고 리뷰를 요청한다. 작성 전에 제목, 본문, 대상 브랜치가 모호하면 확인을 요청한다.

## 주의 사항

- PR을 만들기 전에 브랜치를 원격 저장소에 푸시한다.
- PR은 리뷰가 완료되고 필수 검증이 통과하기 전에는 병합하지 않는다.
- 이 스킬은 새 커밋을 만들지 않는다. 커밋 작업은 `$commit-changes` 스킬을 사용한다.
