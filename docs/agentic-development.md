# AI 원데이 출시 개발 가이드

## 1. 목표와 작업 단위

현재 작업 단위는 기능 하나가 아니라 **프론트엔드 MVP 전체**다. 하나의 Codex 작업에서 문서 확인, 구현, 백엔드 계약 기반 mock 연결, 실제 API 전환, 모바일 검증, Capacitor iOS 빌드까지 연속 수행한다.

이번 릴리스의 성공 기준은 다음과 같다.

1. 검색 또는 현재 위치로 추천을 요청한다.
2. 추천·더보기·상세를 확인한다.
3. 선택한 주차장을 외부 지도에 전달한다.
4. 최종 API 계약과 동일한 mock 또는 실제 API로 모바일 웹 흐름이 끝난다.
5. Capacitor iOS 앱을 실행하고 archive를 만들 준비가 된다.

## 2. 실행 원칙

- 기능별 Clarify → Plan → Tasks → Analyze → 승인 절차를 반복하지 않는다.
- 첫 분석에서 전체 구현 순서를 짧게 정하고 곧바로 수직 흐름을 만든다.
- 사용자의 선택 없이는 결과가 달라지는 실제 차단 사항만 질문한다.
- 로딩 모양, 파일명, 내부 상태 구조처럼 되돌리기 쉬운 결정은 가장 단순하게 구현한다.
- 백엔드가 준비되지 않았으면 `backend-api-contract.md`와 동일한 DTO fixture/mock adapter로 연결한다.
- 실제 API가 준비되면 화면을 바꾸지 않고 adapter 또는 base URL만 전환한다.
- Figma에 없는 상태는 manifest의 V6 대체 패턴으로 구현하며 작업을 멈추지 않는다.
- 자동 테스트, coverage, 광범위한 리팩터링, Android 전용 QA는 첫 iOS 제출의 차단 조건이 아니다.

## 3. 구현 순서

| 순서 | 목표                                   | 종료 조건                                          |
| ---- | -------------------------------------- | -------------------------------------------------- |
| 1    | 앱 셸·route·환경 변수·API/mock adapter | 홈이 모바일 viewport와 iOS safe area에서 표시됨    |
| 2    | 검색 수직 흐름                         | 홈 → 검색 → 목적지 확정 → 방문 조건 → 추천 요청    |
| 3    | 탐색 수직 흐름                         | 결과 → 정렬 → 더보기·상세 → 길찾기 sheet           |
| 4    | 지도·위치                              | 네이버 지도, 600m 원, marker, 위치 허용·거부       |
| 5    | 최근 이용                              | `DISPATCHED`만 저장하고 상세 진입                  |
| 6    | 실제 API 전환                          | 준비된 endpoint의 실제 응답으로 핵심 흐름 성공     |
| 7    | iOS 패키징                             | Capacitor sync, 가능한 환경의 앱 실행·archive 시도 |

한 단계에서 비차단 문제가 생기면 목록에 남기고 다음 단계로 진행한다. 빌드 실패, 앱 시작 크래시, 핵심 흐름 단절, API 계약 불일치, iOS 권한 크래시는 즉시 해결한다.

## 4. Mock과 실제 API

- mock response는 백엔드 계약의 field·enum·nullability를 그대로 사용한다.
- 최소 fixture는 정상 추천 3건, 추천 0건, API 오류다.
- mock 전용 타입이나 화면 분기를 만들지 않는다.
- production 빌드에서 mock이 켜지지 않도록 명시적 환경 변수와 production 기본값을 사용한다.
- 실제 API 응답이 계약과 다르면 프론트에서 임의 보정하지 않고 차이를 보고한다.

## 5. 최소 검증

모든 pnpm 명령은 `client/`를 working directory로 지정한다.

```text
pnpm check
pnpm build
```

수동 검증은 아래 golden path에 집중한다.

1. 목적지 검색 → 방문 시간 입력 → BALANCED 추천 → 상세 → 외부 지도
2. 주변 → 위치 허용 → 자동 입차·출차 → 추천 → 더보기 → 외부 지도
3. 추천 0건 → 목적지 다시 검색
4. 위치 거부와 API 실패 → 앱이 멈추지 않고 재시도 또는 검색 가능
5. iOS에서 지도·safe area·외부 앱 전환 후 복귀

전 브라우저 조합, Android 실기기, 자동 accessibility audit, 성능 benchmark, coverage는 첫 제출의 차단 조건이 아니다.

## 6. 외부 환경

Xcode, Apple signing, 실제 기기 권한, 운영 CORS, HTTPS, 도메인 등록처럼 Codex가 직접 확정할 수 없는 항목은 작업을 멈추지 말고 정확한 차단 원인과 사용자 작업으로 분리해 보고한다.
