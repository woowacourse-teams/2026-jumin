# 테스트 준비와 실행 구간 나누기

given, when, then으로 준비·실행·검증을 구분하되 테스트 흐름에 맞게 인접한 구간을 합쳐 쓴다. Mockito의 mock 설정은 given 또는 given이 포함된 결합 구간에서 실행 코드보다 앞에 둔다.

구간 주석은 `// given`, `// when`, `// then` 또는 이들을 `&`로 합친 이름으로 작성한다. 같은 줄에 설명을 덧붙이지 않고, 추가 설명이 필요하면 해당 코드 앞에 별도의 짧은 주석으로 작성한다.

- 준비와 실행이 짧게 이어지면 `// given & when`을 사용한다.
- 실행과 검증이 하나로 이어지면 `// when & then`을 사용한다.
- 전체 흐름이 간단하면 `// given & when & then`도 사용할 수 있다.
- 구분이 필요한 경계를 기준으로 나누고 빈 구간은 만들지 않는다.

- 범위: 서버 Java 테스트의 단계 주석과 mock 배치
- 상태: 사용자 명시 채택

**설명용 예시**

변경 전

```java
void findsResult() {
    // given
    // when
    when(repository.find()).thenReturn(value);
    var result = service.find();
    // then
    assertThat(result).isEqualTo(value);
}
```

변경 후

```java
void findsResult() {
    // given
    when(repository.find()).thenReturn(value);
    // when
    var result = service.find();
    // then
    assertThat(result).isEqualTo(value);
}
```

근거: mock을 준비하는 when 호출과 테스트 대상을 실행하는 when 구간을 혼동하지 않게 한다. (추론)

- 반례·반론: dd49ed7의 ViewportProductionMigrationIntegrationTest 변경은 given·when·then 주석을 실제로 삭제했다. mock 배치 수정은 반영됐지만 전체 테스트의 일관된 단계 주석 적용은 부분적이며, 철회 이유나 허용 예외 합의는 확인하지 못했다.
- 한계: 프로젝트 테스트에는 when &amp; then 같은 결합 구간도 있다. 불필요한 준비 코드나 빈 단계를 억지로 만들지 않는다.

구간을 합치는 경우에도 구간 이름만 적는다.
