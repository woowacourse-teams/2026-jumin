# 메시지 상수의 키는 대문자 밑줄로 쓰기

메시지 상수와 키를 UPPER_SNAKE_CASE로 쓰고 참조 위치도 함께 맞춘다.

- 범위: 프런트엔드 API·관리자 메시지 상수의 이름과 키
- 상태: 후보 · 논의 동의 · 구현 반영

**설명용 예시**

변경 전

```typescript
const API_ERROR_MESSAGES = { parkingLike: '변경에 실패했습니다.' } as const;
showError(API_ERROR_MESSAGES.parkingLike);
```

변경 후

```typescript
const API_ERROR_MESSAGES = { PARKING_LIKE: '변경에 실패했습니다.' } as const;
showError(API_ERROR_MESSAGES.PARKING_LIKE);
```

근거: 메시지 키가 일반 데이터 필드가 아니라 고정 상수임을 표기로 드러낸다. (추론)

- 반례·반론: 같은 리뷰에서 중복 사용이 없는 검색 문자열까지 상수화하는 것은 과하다는 반론이 있었다. 네이밍 규칙은 모든 문자열의 상수화를 뜻하지 않는다.
- 한계: 문자열의 실제 내용과 API 필드 이름은 이 규칙으로 변경하지 않는다.
