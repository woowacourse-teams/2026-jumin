# 오류 문구 테스트는 기존 상수 재사용하기

이미 정의된 오류 메시지 상수를 import해 사용하고 같은 문자열을 테스트에 복제하지 않는다.

- 범위: 프런트엔드의 클라이언트 오류 문구 expectation과 mock 설정
- 상태: 후보 · 논의 동의 · 구현 반영
- 예외: 서버가 보낸 문구의 전달·파싱·변환 자체를 검증하는 테스트는 그 목적을 명시하고 고정 문자열을 사용할 수 있다.

**설명용 예시**

변경 전

```typescript
expect(result.current.errorMessage).toBe('좋아요를 변경하지 못했어요. 다시 시도해주세요.');
```

변경 후

```typescript
import { API_ERROR_MESSAGES } from '../../api/apiErrorMessages';

expect(result.current.errorMessage).toBe(API_ERROR_MESSAGES.PARKING_LIKE);
```

근거: 안내 문구를 바꿀 때 테스트에 복제된 문자열을 따로 수정할 필요를 줄인다. (추론)

- 한계: 정확한 제품 문안 자체를 별도 계약으로 검증하는지와 기존 fallback 상수를 재사용하는지 구분한다.
