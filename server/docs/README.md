# 의사결정 기록

프로젝트에 영향을 주는 도메인, API·데이터, 보안, 의존성, 인프라, 배포, 운영 결정은 이 디렉터리에 Markdown으로 기록한다. 결정 전의 가정과 미확인 사항도 구분해서 남긴다. 이 파일을 결정 기록의 기준 목록으로 사용한다.

## 작성 방법

- 새 기록은 [`TEMPLATE.md`](TEMPLATE.md)를 복사해 시작한다.
- 파일명은 `YYYY-MM-DD-짧은-주제.md` 형식으로 쓴다.
- 결정 상태는 `Proposed`, `Accepted`, `Rejected`, `Superseded`, `Deprecated`, `Withdrawn` 중 하나로 표시한다.
- 사용자 동작, 도메인 경계, API·데이터 계약, 보안, 의존성, 인프라, 배포, 운영 방식에 영향을 주는 새 결정은 대안 검토 중 `Proposed` 초안으로 시작하고 구현 전에 선택 결과를 기록한다. 기존 결정을 그대로 적용하면 새 기록을 복제하지 말고 적용한 결정에 연결한다.
- 한 기록에는 하나의 결정 질문을 담고, 관련된 대안·기준·근거·결과·검증 조건을 적는다. 간단한 결정은 템플릿을 짧게 작성하고, 영향이 크거나 되돌리기 어려운 결정은 충분한 대안 비교와 전환·복구 계획을 남긴다.
- 기존 기록의 결정을 바꾸면 과거 내용을 고쳐 쓰지 말고 새 기록을 만들고 `Supersedes`로 연결한다.
- 새 기록은 아래 결정 목록에 연결한다. 부분적으로 대체할 때는 대체 범위를 명시한다.

기존 결정 문서는 이력을 보존하기 위해 현재 위치와 내용을 유지한다. 과거 문서는 각 결정 당시의 사실과 상태를 기록하며, 현행 운영 상태는 코드·설정·운영 증거로 별도 확인한다.
