# AI UX 평가 실행기

이 디렉터리는 [기획안](https://app.notion.com/p/ai-4126a8c6159b800d83e3fdd5e7467dca?source=copy_link)의 연결 PoC와 로컬 CLI다. 가상 화면에서는 공통 과제를 기준 조건과 세 가상 페르소나로 각각 실행할 수 있다. 로컬 주민 화면을 위한 제한된 스모크와 두 실제 버전 연결 경로를 제공한다. 사용자 승인 후 역사적 PMF 전후 두 프런트에서 서울역·기본 1시간 과제를 여섯 번 실행해 도구 흐름을 확인했다. 사람의 UI 재현 검토는 남아 있으며, 원래 계획의 2시간 과제·반복 파일럿·실제 사용자 검증은 미완료다.

## 마무리 검토: 현재 지원 범위와 다음 사용

현재는 가상 과제(`nearby-parking`, `select-parking`), 실제 검색 열기(`local-open-search`, 기준만), 실제 기본 1시간 선택(`local-one-hour-parking`, 기준·요금·도보)을 지원한다. 실제 과제는 서울역 검색 → 지정 목적지 선택 → 기본 1시간 → 주차장 선택 → 길찾기 **앱 선택 화면** 도달이며 외부 앱 실행은 차단한다. `local-select-parking`의 2시간 과제는 준비 전 차단된다. 이번 역사적 비교는 원래 기획 전체의 완료가 아니다.

### 이번 실제 결과와 판단 경계

2026-11-11 실제 A `1a43d7c`(PMF 설문 전)와 B `31ea0a6`(후)를 비교했다. B는 설문 컴포넌트·표시 상태·공통 Modal·지도 레이아웃 네 파일을 변경했고 API·패키지·잠금 파일은 같았다. **독립 완료 5회·미완료 1회라는 관찰이며 일반 성공률이 아니다.** 아래 요약만으로 리뷰할 수 있고 비공개 상세 결과는 Git에 포함하지 않는다.

총 55요청·55응답에서 입력 168,324·출력 5,217토큰을 확인했다. 로컬 모델 보고값이며 과금 토큰이 아니다. num_ctx는 요청당 설정이고 실행 누적 한도가 아니다.

- 독립 확인: A 세 조건·B 기준·B 도보는 지정 목적지·1시간·주차장·길찾기 모달 완료. B 기준은 `action_limit`과 독립 `passed`를 함께 보존한다. B 요금은 추천 화면까지 확인했으나 선택 근거 미확인·길찾기 모달 미도달이며 `model_output_limit`이다. 출력 제한은 UI 결함이나 설문 효과의 증거가 아니다.
- 비교 범위: 기준 쌍은 핵심 요청이 다르다(`different_request`). 요금·도보 쌍은 핵심 주차 조회의 쿼리·상태·응답만 같았다. 전체 데이터 동일성은 미확인이다. 입력 토큰 보고값의 문맥 설정 초과만으로 잘림을 확정하지 않는다. 실행 시간에는 모델 추론·도구 대기와 준비·검증이 포함된다.
- 선택 근거: 완료한 다섯 실행은 렌더링된 23후보에 선택을 유일하게 연결했다. 요금 숫자 근거는 각 2후보에서 확보하지 못해 비교 불가, 도보 선택은 관측 범위의 최저가 아니었다. UI 정보 부재나 모델이 정보를 읽고 비교했음을 입증하지 않는다. B 요금의 후보 비교는 미확인이다.
- 제한: 외부 설문 차단, 설문에 맞춰 개발된 modal-focus-v3, 현재 dev 데이터·복제 의존성, 조건별 1회다. 화면 우열·새 기능 효과·일반 성공률·실제 사용자 행동을 추론하지 않는다. 사람의 UI 검토를 대신 완료 처리하지 않는다.

### 실제 비교 재실행 명령

이 체크아웃의 작업용 모델은 보존돼 있지만 Git으로 전달되지 않는다. 검증 환경은 macOS arm64, Node 24.4.0, Ollama 0.40.16, qwen3.5:9b(MLX/nvfp4)였다. digest는 `d63f830f28d515fefea546f213fca7a75e9dd5176ef51a6deabc952d1c99a911`이다. 다른 배포본의 메타데이터 호환성은 미확인이다. 모델 약 7.1GiB·실행 파일 약 579MiB를 `.runtime/models`·`.runtime/ollama`에 보존했고 압축 파일 등을 포함한 런타임은 약 7.9GiB였다. 다른 팀원은 도구 호출 지원 모델·서버를 별도로 준비해야 한다. 메모리·3000/11435 포트·지도 ID 존재·dev 조회·보호 정책을 확인하고 아래 작업용 서버를 먼저 시작한다. 실행기는 프런트를 직접 시작하므로 별도 `pnpm dev`를 띄우지 않는다. 키는 원래 env에서 메모리로 읽고 다른 사용자 서버·모델이나 기존 client/node_modules는 변경하지 않는다.

```sh
cd tools/ai-ux-eval
env HOME="$PWD/.runtime/home" OLLAMA_MODELS="$PWD/.runtime/models" \
  OLLAMA_HOST=127.0.0.1:11435 OLLAMA_NO_CLOUD=1 .runtime/ollama/ollama serve
```

별도 터미널의 같은 디렉터리에서 아래 설정 예시를 준비·검토·승인한 뒤 실행한다. 역사적 재현도 두 커밋을 별도 디렉터리에 준비해야 하며 로컬 비공개 경로는 공유하지 않는다:

```sh
API_PROXY_TARGET=https://dev.jucha.info node --env-file-if-exists=../../client/.env local-ab.mjs \
  --config .runtime/versions.json \
  --scenario local-one-hour-parking --local-url http://localhost:3000 \
  --ollama-url http://127.0.0.1:11435 --num-predict 1024
```

기존 검증된 qwen3.5:9b·modal-focus-v3·latest-screen-v1과 temperature 0, num_ctx 4096, think false, 행동 10회·연속 오류 3회·행동당 5초·전체 300초를 사용한다. 끝나면 이 작업에서 시작한 서버만 종료한다. 단건·가상 실행 명령은 아래에 있다.

### 신규 두 화면 연결 및 사람 검토 순서

1. 두 실제 프런트의 정확한 커밋·독립 소스 경로·의존성·변경 범위·공통 과제와 조회 계약을 준비한다. `.runtime/versions.json`의 `commit`, `clientDirectory`, 승인 필드와 `order`를 새 대상에 맞춘다. 과거 승인을 새 화면에 승계하지 않는다. `scenarioReady/changeReviewed/dataSourceReviewed`는 사람의 새 승인 범위만 반영하며 데이터 동일성을 보증하는 필드가 아니다.
2. 같은 과제·모델·지침·제한·backend를 유지한다. 과제가 달라지면 시나리오 목표와 독립 완료 근거, 필요한 조회 허용 범위를 먼저 검토·검증한다. 2시간 UI가 실제 추가되기 전에는 준비 상태를 true로 바꾸지 않는다. 준비된 기능을 모델 없는 경로에서 확인하고, 사람 승인 후에 비교를 실행한다.
3. 보고서의 실제 순서·커밋·조건 일치부터 읽고, 조건별 종료 이유·자기 보고·독립 판정·도달 상태를 따로 본다. `null/unavailable`을 false로 바꾸지 않는다. 핵심 요청 차이와 전체 데이터 미확인을 확인한 뒤 행동·시간을 해석한다.
4. 아래 세 후보를 사람이 새 세션에서 확인한다. 모달 경계, 대상 미확인 MCP 오류, 출력 제한은 현재 재현된 UI 결함이 아니다. 원문이 남지 않은 과거 대상·의도·상태는 추정하지 않는다. 사람이 확인한 사실과 새 확인 결과를 별도로 기록한다.

남은 범위는 **2시간 UI와 완료 근거 검증**, 신규 화면에 대한 사람 승인, 첫 보고서 유용성 검토 후의 반복 파일럿·일반 AI 직접 탐색 비교, 실제 사용자 검증이다. 이번 1시간 역사적 결과를 본 반복 실험에 합산하지 않는다.

## 설치와 실행 예시

Node.js 24, pnpm 11.20.0, Chromium이 필요하다. 별도 pnpm 패키지이며 client/node_modules는 재구성하지 않는다. 기존 client deepmerge 설치 패치 이슈를 해결했다고 주장하지 않는다.

```sh
cd tools/ai-ux-eval
pnpm install --frozen-lockfile
pnpm exec playwright install chromium

# 실제 모델·dev 없이 로컬 브라우저와 대역 모델만 사용하는 검사
pnpm check:browser
pnpm test

# 도구 호출 지원 Ollama 모델이 준비된 경우의 가상 단건/비교
pnpm eval --scenario select-parking --persona price --model qwen3.5:9b \
  --ollama-url http://127.0.0.1:11435 --num-predict 1024
pnpm compare:fixture --model qwen3.5:9b --ollama-url http://127.0.0.1:11435

# 실제 기본 1시간 단건: 프런트는 실행기가 시작함
API_PROXY_TARGET=https://dev.jucha.info pnpm eval --mode local \
  --local-url http://localhost:3000 --scenario local-one-hour-parking \
  --persona baseline --model qwen3.5:9b --ollama-url http://127.0.0.1:11435 \
  --num-predict 1024 --report
```

기존 연결 PoC는 `pnpm poc`로 유지한다. `OLLAMA_MODEL`·`OLLAMA_BASE_URL`을 지정할 수 있다. 일반 단건 CLI 기본값은 model-defaults.json의 qwen2.5:7b·temperature 0·num_ctx 4096·num_predict 256·think false다. 이번 실제 비교는 위의 명시 설정을 사용했다. `pnpm eval --help`에서 전체 옵션을 확인한다.

### 버전 설정 예시

각 소스에는 src·package.json·별도로 준비한 의존성이 있어야 한다. 정확한 커밋과 파일의 일치는 준비 시 검토한다. 실행기는 동일 경로·동일 부분 소스 지문·미승인 상태를 거부하고 실행 중 소스 변화도 확인한다. 지문은 환경 파일·의존성까지 포함한 전체 환경 동일성을 증명하지 않는다.

`.runtime/versions.json`의 승인 전 예시이며 승인 후 해당 범위의 준비 필드만 바꾼다. order는 두 버전 × 세 조건을 정확히 한 번씩 포함해야 한다.

```json
{
  "order": ["A:baseline", "B:baseline", "B:price", "A:price", "A:walking", "B:walking"],
  "versions": [
    {
      "id": "A",
      "commit": "실제_40자리_커밋",
      "clientDirectory": "/absolute/path/to/a/client",
      "scenarioReady": false,
      "changeReviewed": false,
      "dataSourceReviewed": false
    },
    {
      "id": "B",
      "commit": "실제_40자리_커밋",
      "clientDirectory": "/absolute/path/to/b/client",
      "scenarioReady": false,
      "changeReviewed": false,
      "dataSourceReviewed": false
    }
  ]
}
```

실행마다 새 임시 프로필·대화를 쓰고 종료 시 정리한다. 모델 미완료는 다음 조건으로 진행하지만 공통 환경·보호·연결·정리 오류는 중단한다. 실패한 요청과 모달 사전 거절도 행동 한도에 포함한다. 전체 일정 완료가 모든 과제 완료라는 뜻은 아니다.

## 보호·보고서와 검증 범위

앱 첫 스크립트 전에 같은 브라우저 컨텍스트에 analytics_opt_out을 설정하고 GA·Clarity·Sentry 설정을 비운다. 서비스 워커·쓰기·분석·외부 이동·리디렉션·외부 앱 실행을 차단하고 확인한 조회만 허용한다. 초기 차단을 별도 보존하며 모델 시작 후 새 쓰기·이동 차단은 즉시 중단한다. 시점만으로 모델이 유발했다고 단정하지 않는다.

modal-focus-v3는 모든 실제 조건에 동일하다. 확인된 모달 뒤 클릭·입력은 실행하지 않고 최신 화면과 오류를 모델에 전달한다. 모달을 대신 닫거나 정답을 지정하지 않는다. 모델이 고른 입력란을 먼저 포커스하며 화면이 바뀌면 입력을 보류하고 모델이 다시 선택한다. latest-screen-v1은 과제·관점·범주형 이력·최신 화면·직전 결과를 유지하고 이전 화면의 중복을 줄인다. 현재 후보를 숨기거나 화면을 자르지 않는다.

실제 화면 원문·스크린샷·입력값·지도 키·원본 네트워크 정보는 저장하지 않는다. 필요한 화면은 민감정보를 가려 메모리에서 모델에 전달한다. 구현·테스트한 범위의 보호이며 모든 개인정보 형태의 완전한 탐지를 보장하지 않는다.

reports/·diagnostics/·.runtime/·환경 파일은 Git에서 제외한다. 비공개 자료는 삭제하지 않는다. 보고서는 디렉터리 0700·파일 0600이며 JSON과 Markdown으로 생성된다. 기존 안전한 구조화 결과의 재정리는 `pnpm report:local --input <result.json>`이며 가져온 출처는 미검증으로 표시한다. 가상 진단은 `--diagnostics`로 켜고 실제 모드에는 금지한다. 모델 없는 초기 화면 진단은 `pnpm diagnose:local`이다.

핵심 주차 조회는 독립 확인한 목적지와 조회 목적지를 연결하고 과제의 시간을 검증한 범위만 비교한다. 전체 트랜잭션은 필수 조회·지도 리소스가 누락되거나 실패하면 미확인이다. 세션별 헤더·시간·탐색 차이도 있을 수 있어 요청 차이를 데이터 변경으로 해석하지 않는다. 선호·정보 읽기·실제 비교 과정은 선택 결과만으로 판단하지 않는다.

기존 도구 자동 검사 92개는 모델 대역·가상/로컬 서버에서 통과했다. 실제 모델 결과는 위의 6회이며 별개로 해석한다. 독립 JavaScript CLI여서 TypeScript 빌드·번들 단계는 없다. Node 구문·린트·포맷과 관련 자동 검사를 사용한다. 앱 E2E·기존 설치·배포 설정은 제출 범위에서 변경하지 않는다.
